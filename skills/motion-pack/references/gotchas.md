# Gotchas (full list, from the module builders and earlier ANVE video work)

## HyperFrames (0.8.142)

- **Timed clips vanish outside their window.** A clip is hidden outside `[data-start, data-start + data-duration]`. A two-layer transition needs the outgoing clip to run past the cut and the incoming clip to start before it. `templates/_shared/txplan.mjs` does this with `txPlan()` + `span()`, clamped to half of each neighbouring shot. When you add a new template, pass every timed element through `span()`.
- **Never tween a timed `.clip` or `<video>` directly.** Animate an untimed wrapper (`#w-<id>`).
- **`z-index` on the overlay container breaks blending.** It creates a stacking context and isolates `mix-blend-mode` (grain and vignette stop blending), so set z on the canvases.
- **Lint warnings do not block a render.** Use `--strict` to make errors block.
- **Default quality `looks` is CRF 16.** That gives about 18 Mb/s, 34 MB for a 15 s 1080p file. Pass `--crf 23` for demos and reviews, and use the default only for masters.
- **Pin the version:** `npx --yes hyperframes@0.8.142 ...`. Everything in this file was measured on 0.8.142.
- **The whole track drops if the AAC is too hot.** If the encoded AAC true peak is over -1 dBTP, HyperFrames lowers the entire track, and it logs this only with `--debug`. The 30 s ad lost 1 dB this way. The mixer's AAC probes catch it, so keep the WAV at -1.5 dBTP.
- **GL in HyperFrames is proven with canvas sources only.** A `<video>` used as a WebGL texture during a render is untested, so draw video frames into a canvas or use the DOM back-end.
- **UI clicks overshoot HyperFrames' own AAC more than the mixer's probe predicts.** The UI-kit demo's master sat at -1.5 dBTP with mixer AAC probes at -1.1 / -1.2, yet HyperFrames logged `Audio lowered by 2.2 dB` and the delivered file measured -16.4 LUFS. Set `ceilingDb: -2.5` in the plan (read by `templates/_shared/audio.py`) for click-dense UI mixes; the re-render delivered -14.1 LUFS / -1.5 dBTP with nothing lowered. Always grep the render log for `lowered`.
- **A mix that starts on a hit can make HyperFrames lower the whole track by 4–5 dB.** HyperFrames re-encodes its AAC mix (AAC to AAC) before muxing; a full-level transient in the first ~15 ms overshoots by several dB in the second encode even when the WAV sits at −2 dBTP, and the whole track is then lowered (the demo-type-layout render dropped to −18.9 LUFS). Fade the first 40 ms in (`plan.fadeInMs: 40` in `templates/_shared/audio.py`) and set `plan.ceilingDb: -2.0` when UI clicks are dense; then check `Audio lowered by` in the render log.
- **The GSAP binding is one paused proxy tween per transition window, driving `p` linearly.** The easing lives inside `applyDom`, so do not add an ease on the proxy.

## Proof film (templates/proof-film)

- **One camera over a wide world needs two wrappers.** cam2d scales a wrapper about ITS OWN centre, so scaling a world several frames wide drifts every panel but the middle one. The template pans the world (`#world`, `pan2d` legs) inside a frame-sized wrapper (`#cam`) that carries the zoom about the frame centre; then `W/2 + zoom * (cell centre - focus)` holds and a cell centre projects to the frame centre whenever the camera rests (`panels.mjs mapCell`, tested).
- **A slow push moves the content out of the safe zone.** A 3.5% dwell push takes a point at the edge of the 9:16 conservative rect past it. `safeInset` pulls the rect in by `1 + push` and every box and footer is laid out in the pulled-in rect.
- **Start a panel's build while the camera is still settling.** A cell whose content starts only after the camera arrives leaves empty paper in the frame for a few tenths of a second mid-move (seen with a 0.4 s lead); `timing.enterS` 0.15 s keeps something moving in the frame at every moment.
- **Dense UI cues tripped HyperFrames' AAC again.** With `ceilingDb: -2.0` the render logged `Audio lowered by 0.9 dB` (delivered -15.2 LUFS) and with `-2.5` it logged 0.6 dB (-14.9 LUFS) although the mixer's own AAC probes read -2.1 dBTP; `-3.0` delivered -14.2 LUFS / -1.9 dBTP with nothing lowered. The bed's kicks, not the cues, sit at the ceiling. Grep the render log for `lowered` after every change to the cue list.
- **A cue time at half a frame rounds two ways.** The mixer places `round(t * fps)` in python (half to even) and a JS plan can mean the other neighbour: `ears` reported cues 1.0 f off (anchors 0.79). `buildPlan` quantises every cue to a whole frame (anchors 0.97).
- **Under a voice, cues sit over the UN-ducked bed.** The mixer's level reference is the bed before it ducks, so a tick in a sentence is as loud as the bed was before the duck. Set the cue's `overVoDb` (the plan cue field `templates/_shared/audio.py` hands to the mixer) to put it under the voice.
- **A pulsing bed hides its own duck from `ears`.** `ears` reads the duck in the band under 100 Hz and the proof bed's kick-locked bass pulses: with `duckDb: 12` the median read 9.4 dB (the music stem itself measured 7.7 dB between a line and its breath) and one line failed; `duckDb: 16` reads an 11-13 dB median, speech scores 8, one warning stays on the longest line. For a VO film pick the duck from the stems, not the plan.
- **The `--set` parser turns whitespace into 0.** `make.mjs` and `cues.mjs` read `k=  ` as the number 0 (`+'  ' === 0`); the gate counts a non-string `source` or `method` as missing, so it still fails with the field named.
- **Two root compositions in one folder fail `hyperframes lint`.** `index.html` plus `index-tall.html` is `multiple_root_compositions` (an error; `--strict` would block the render, and the runtime may play the audio twice). The 9:16 page is its own project, `templates/proof-film/tall/index.html` with its own `assets/`; `hyperframes snapshot` and `render` take that folder.
- **A pulsing bed that merely falls 40 dB still reads as a decay.** `ears` (refstudy) calls the last 2 s a quiet hold only if they are 10 dB under the body AND flat (p90 - p10 of the 0.25 s curve within 8 dB); a bed's kick pulse is the same 10 dB at any gain. Put a steady floor under the hold instead: `sfx/amb/room_tone` as a plan cue with `overBedDb: -26` (a loop cue defaults to -10 dB under the bed, far too loud there) while the bed falls to -40: the delivered file reads `quiet hold`, 24 dB under the body (`ears/tests/test_proof_film_hold.py`).
- **A number is more than the digits 0-9.** A first gate that tested `/[0-9%$]/` passed `６０％`, `٦٠`, `६०`, `²`, `½`, `①`, `ten-times` and a VO transcript that said "sixty percent". The gate now uses `\p{N}` + currency signs + the percent signs, a list of number words, and it checks the brand name, the URL, the axis units and the transcript (`numberIn`). "One", ordinals and "a lot cheaper" still pass: a gate refuses forms, not lies.
- **Zero-width characters hide a number word.** `s<ZWSP>ixty` and a soft hyphen inside `sixty` split the word for a tokenizer; fullwidth `ｓｉｘｔｙ` is not ASCII. `numberIn` drops `\p{Cf}` and folds with NFKC before it looks for number words, and tests the raw text for digits first (NFKC turns the Roman numeral sign `Ⅷ` into the letters `VIII`).
- **A transcript entry under the wrong key is skipped, not read.** A words.json with `word` instead of `w` used to pass the voice check (`w` was `undefined`, so nothing was tested). `gateProblems` now refuses an entry that is not `{w: "text", s, e}` in seconds and in order, an empty list, and `vo.audio` without `vo.words`.
- **The staged page runs the copy under `assets/mp/`, not your edit.** `make.mjs` hard-links `panels.mjs` into `assets/mp/` (and `tall/assets/mp/`) on every run; an editor, `git checkout` or a mutation test that REPLACES the source file leaves the link on the old inode. A 9:16 render made after a `git checkout panels.mjs` had a mutated copy and no ILLUSTRATIVE pill while the 16:9 one had it. Always `node make.mjs` (both formats) right before a render, and `cmp` the staged copy against the source if a render looks wrong.
- **A source of "." is not a source.** `blank()` only caught empty and whitespace. `weak()` also refuses filler (`n/a`, `tbd`, `.`), text with fewer than two distinct letters, a method under eight letters or two words, and a method that repeats the source; it still cannot tell a true source from a made-up one.
- **A 9:16 plate of a landscape diagram is 7 px type.** `ui.branchTrace` scaled to a 1080 px wide frame prints 15 px labels at 7 px: the gate refuses `trace` on `format: tall` instead of warning.
- **`hyperframes snapshot` lets you look before a render.** `npx -y hyperframes@0.8.142 snapshot . --at 6,15,25 --no-end --describe false -o /tmp/snap` (`--describe false`: the Gemini analysis runs when `GEMINI_API_KEY` is set, a cloud call).

## Transitions

- **DOM gaps.** The DOM back-end covers 13 of 23 transitions. Its limits:
  - spin shows the background instead of mirrored edges.
  - whip has no RGB fringe.
  - lumaWipe supports only linear and radial.
  - iris star and roundRect are approximations.
  - match has no guides.
- **GL-only keys hard-cut in DOM templates.** These are glitch, ink, filmBurn, lightLeak, morph, zoomThrough, pagePeel, pixelSort and maskReveal. Each is logged as `transitions todo`.
- **Two transitions are approximations.** pixelSort is a max-luma streak, not a true sort. morph is a luma-gradient warp dissolve, not optical flow.
- **The three.js pass is parity-tested against r185** (`transitions/tools/three-parity.sh`, with `THREE_BUILD` pointing at a local three.js build). The kit (`objects/kit/`) loads r160 from CDN, so do a first-use check inside a kit scene before a hero use.
- **sharedElement clones are snapshots.** The DOM back-end clones each `[data-share]` element (computed styles copied) the first time a frame inside the window is drawn. A frame-parallel or out-of-order render can enter the window anywhere, so hold shared elements still inside the window (draw an animated one at `min(t, t0)` in shot A and `max(t, t1)` in shot B); a `<video>` inside a shared element freezes.
- **sketchToRender needs edges.** Flat gradients give no line art (the DOM Laplacian and the GL Sobel both read luminance edges); a plate with busy texture turns into hatching. Judge the cut frame.
- **Flash and photosensitivity.** Use `peak: 0.7` and no more than 3 flashes per second for anything broadcast-adjacent. Check WCAG flash thresholds.

## Sound

- **Hit contract.** The anchor sample lands at `(F + 1) x SR / fps`: one frame after the visual (the rule from ANVE's v9 launch film). Risers end one frame **before** the hit.
- **The library is normalised to -6 dBFS peak.** Real levels come from the mixer's over-bed solver (hero +4.5, whoosh +2, ui +4, logo +5 dB over the bed). Never gain by hand.
- **Sub-heavy cues are not phone-safe.** `phone_safe=false` means the cue drops more than 6 dB on a phone speaker. Pair it with a mid-range cue (lint R12).
- **Sound ids use the registry segment, not the manifest category.** The transition sounds are `sfx/tx/*` and the impacts `sfx/hit/*` (category names `transition` and `impact` are not ids). The music-mixer path of `templates/_shared/audio.py` skips an unknown id silently, so run `python3 tools/check_ids.py` before every mix and compare the cue count it prints.
- **A dense SFX cue sheet can still trip the AAC probe.** The 16 s cards demo decoded 0.9 LU quiet at a -1.5 dBTP WAV ceiling (HyperFrames lowered the whole track); `plan.masterCeilingDb: -2.0` fixed it (-14.2 LUFS / -1.6 dBTP decoded).
- **A pack bed's kick lands on frame F; the SFX land on F + 1.** Onset-based sync checks confuse the two when a cue sits one frame after a downbeat. `ears` finds each cue by matching the exact take the mixer placed, so it measures 0.0 frames off on the pack's own mixes, and it reports a masked cue as not detectable rather than off.
- **Ducking is measured against the music next to the line.** Wall-to-wall VO leaves no music-only stretch, so `ears` says "not measurable" there. Its speech detector misses lines, so without a transcript it measures ducking but does not judge it. The AnveVoice film's music dips 4-8 dB under its lines (stems agree within 1 dB), less than the mixer's 9 dB envelope.
- **`ears` can only read a duck against a music-only stretch of about 1 s or more, and the mixer's own 9 dB is the threshold.** The reference starts 0.4 s after the line (the duck releases over about 0.35 s) and ends 0.15 s before the next, so a 0.5 s breath gives nothing to measure and a 1.1 s breath gives 0.55 s. A nominal 9.0 dB duck therefore reads 8.7-8.9 dB, and it is measured below 100 Hz, so a bed with sparse bass notes (`bed_documentary_marimba_loop8`, `bed_acoustic_folk_pluck_loop8`) reads 1-9 dB depending on whether a note falls in the window. For a VO-led film set `plan.duckDb: 12` (cue sheet `vo.duck_db`; the default stays 9) and use a bed with a steady low end (`bed_lofi_warm_loop8`, `bed_uplift_corporate_loop8`, `bed_ambient_pad_loop8`); give the film a few 1.1 s "music beats" and keep the bed up for the first 1.8 s of the end card, or the only reference is the faded tail. `templates/multi-voice-doc` does all of this and passes `ears/speech` (ducking median 12 dB, speech 21 dB over the music, 160 wpm).
- **Placeholder speech must run at a human pace.** Hand-timed placeholder words at 0.27 s each with 0.04 s gaps are 195 words per minute and `ears` calls the voice rushed (house range 110-175). Time placeholder transcripts at about 160 wpm (about 0.38 s a word with the gaps), and make a synthetic guide signal vary per word or `ears/repetition` reads its bursts as one repeating sound effect.
- **No human listening pass yet.** Everything was verified by measurement and spectrograms. The glass, bell, metal and bubble tables are research grade C, and the babble, boing and formant voices need one ear pass before a hero use.
- **Loudness targets.**
  - IG, TikTok, X and LinkedIn publish no loudness spec (grade D).
  - The house master is -14 LUFS-I with TP <= -1.5.
  - Festival and broadcast is -23 LUFS / -1 dBTP as a separate master.
- **Quiet you meant looks like a fault until you plan it.** `ears` warns of "dead air" for 2 s or more of near-silence (>= 20 dB under the programme) and of "first audible sound" after frame 3. A quiet open (<= 2 s), a reset dip or trailer gap (<= 4 s) and an end-card hold (<= 9 s) are first-class shapes: mark them in `plan.audio.quiet` `[{t: [a, b], kind: open|dip|gap|hold, why}]` and ears judges them as intended, leaves them out of the loudness range, and reports the ending shape. A planned region longer than its house maximum still warns.
- **Cut sync is not one rule.** The >= 60% of cuts within 2 frames of an onset rule is for music-led, cut-driven pieces. For a VO-led film set `plan.audio.mode: "vo"` (cuts under the voice, none inside a word; needs word timings) and for a few-cut film `"continuous"` (motion events on onsets). Scoring a VO documentary or a no-cut proof film in `music` mode produces a failing sync score that means nothing (round 4/5: the tier-A VO films sat at 40-59%).
- **A sync share is not evidence until you read its chance level.** At 3 to 5 audio onsets a second, a third to two thirds of the timeline sits inside the 2-frame windows, so a 40-65% share of cuts or visual events "on an onset" is what luck gives. `refstudy` now prints `chance_share`, `lift`, `z_vs_chance` and `reading` next to every sync share (motion and cut); only `above chance` (z >= 2) is sync. Local check: a beat-built edit read 0.94 against 0.53 chance; a film not built to the beat read 0.49 against 0.45.
- **`music/bed_trailer_arc` is not a loop and cannot be trimmed anywhere.** Never loop or crossfade it into itself and never cut inside or after `gap_start`: the gap, crescendo, hit and hold keep fixed beat lengths. Fit a cut by re-rendering with `render_trailer(act_bars=(a1, a2, a3))` (whole bars, acts 1-3). Its loudness range is wide by design (13.5 LU without the planned regions; ears warns above 10): that is the build, not a mix fault.
- **Count crackle in the band it lives in.** An onset counter on the full signal counts the electric buzz's own pulses: on the zap-off it rose (25 then 47 onsets per half) while the sparks thinned from 80 to 4 per quarter second. Test sparks as impulsive energy above 3 kHz (`sfx/tests/test_elec.py`: high-band kurtosis per half second, and 1 ms envelope peaks over a file-wide median).
- **Most pack beds are bass-heavy.** Measured with the `ears` / refstudy definition (energy under 150 Hz), only a few beds sit in the 20-36% range of the proof and explainer references (`music/README.md`: playful_bounce, chiptune, comedy_pizzicato sting, tabla keherwa / dadra and the like); the corporate, ambient and cinematic beds are 48-70%. Check with `ears/listen.py --role proof`.
- **HyperFrames sound integration is mode A only:** one baked `mix.wav` at 0. Per-clip `<audio>` with `data-start = (F + 1)/fps` is not built yet.
- **Talking-head demo.** The SFX stem sits under the input's own audio, so its LUFS is low on purpose (around -37 for the stem alone).

- **Sound shas are per CPU platform; anchors must not be.** The same recipes with the same pinned numpy / scipy / numba give 248 of 301 sounds one 24-bit LSB apart on x86-64 Linux vs arm64 macOS (-138 dBFS, inaudible), so a sha only matches where the manifest was built. That LSB used to move two anchors: argmax picked the other of two near-equal peaks (`snd.cartoon.cuckoo` 681 vs 181 ms, `snd.device.phone_ring_synth` 842 vs 1942 ms). `registry.peak_anchor` now takes the first sample within 1e-5 of the peak, and CI checks every non-sha manifest field against the commit after the rebuild (`tools/check_generated.py --ignore-field sha`).
- **A test after a generator compares the code with itself.** `sfx/build_library.py` rewrites `sfx/manifest.json` before the tests read it, so a recipe change the commit does not reflect passed every sha test. Run `tools/check_generated.py <file>` right after any generator (CI does, for the sfx, music and layers / type / camera manifests).

## Type and captions

- **UI-kit text widths are estimated.** `ui.*` sizes chips and pills from `textW` (no DOM measurement), so a long label can overrun its chip; check the sheet. The prompt caret is a `<tspan>` after the typed text, so it always sits right after the glyphs.
- **Round-3 UI parts measure text, so fonts must be in before the first frame.** `ui.liveTranscript` wraps turns and `ui.wordRegenerate` / `ui.tabPillNav` size words with `measure()` (canvas metrics in the browser). A frame drawn before Manrope loads wraps with the fallback font. Kick off `document.fonts.load()` for the weights you use and repaint the current time when they resolve (`templates/demo-r3-ui/make.mjs`).
- **A spinner inside a looping part must turn a whole number of times per loop.** The kit spinner turns 1.15 times a second, so a loop of 2.2 s does not repeat exactly; `ui.windowWall` drives its spinners from the loop phase (3 turns per loop) so frame t and t + period are identical (tested).
- **Canvas text and `measure()` use the fallback font until the face is in, and canvas state leaks between frames.** `layers` `embeddingCloud` (the query chip) and `epicycleDraw` (the readout) draw text on a canvas, and `type.iconMergeLockup`, `.flankWords`, `.textOnPath` and `.behindSubject` size their words with `measure()`. A face that has not been used yet is fetched on first use, so frame 0 is drawn in the fallback and a later frame in Manrope: a pixel test showed the same t differing after another t. Load the faces before the first frame (`document.fonts.load('600 26px Manrope')` and the Plex Mono weight, as `layers/demo/r45.html` and `templates/demo-r45-type` do) and repaint the current time once they land. Set `ctx.font` BEFORE `measureText`: the chip width once came from whatever font the previous frame had left on the context.
- **A Fourier drawing is periodic.** `layers.epicycleDraw` with a closed outline is sampled once round; an open path is traced there and back (`closed: false`, or `auto` when the path does not return to its start) so no chord is drawn between its ends. With 512 samples the bird's corners were 1.5 px off the input; 1024 samples give Hausdorff under 0.7 px on every preset path. The DFT is O(samples squared) and cached per path: change the path only between renders.
- **`type.behindSubject` is only as good as the matte you give it.** The pack makes no mattes. Give a PNG with alpha (`matteMode: 'alpha'`) or a luminance image; `edge: 'hard'` thresholds the matte at 0.5. A VIDEO alpha cannot play inside the SVG (HyperFrames owns video playback): turn it into a PNG sequence with `python3 tools/alpha_frames.py subject.webm out/matte` (VP9 alpha needs ffmpeg's libvpx decoder: the native VP9 decoder drops the alpha plane; `--mode luma` for a grey matte video) and pass the printed `matte: { frames, fps, count }`. Its labels fit the safe width through `measure()`, so the fonts must be loaded before the first frame. A matte that is a data-URL `<image>` decodes after it is inserted: wait before a screenshot (the Chrome test sleeps 500 ms), or a frame grabbed too early shows the type un-occluded.
- **`type.electricOutline` and its sound.** It cues `sfx/elec/arc` (the synthesised arc, round-robin); the id lives in ONE constant, `ELECTRIC_SOUND` in `type/gfx/r45-glyph.js` (the cue table and `GFX_SFX` both read it), and `type/tests/r45type.test.mjs` fails if the constant is not the pairing. For a lit sign that stays on, put `sfx/elec/crackle_loop` under it and end it with `until_frame` (bundle `neon_power_on`). Its crackle is seeded per crackle frame (15 per second by default), so two renders are identical. The halo: mount overlay `glow` with `electricGlowPools(params, ctx)` (the pool's `y` is measured from the BOTTOM of the frame, the overlay's own convention) ABOVE a plate that is opaque (it is screen light, like a sign lighting a wall); an overlay mounted below an opaque plate is invisible.
- **Layer images load asynchronously: wait for them like fonts.** `layers` `embeddingCloud` and `hexMosaic` take `images` (URLs, data URLs or decoded images). Each source loads ONCE (a shared cache, not one `Image` per tile per frame) and draws only when decoded; until then the tile is the placeholder, so a frame grabbed before `await stack.ready()` differs from the same t afterwards (the Chrome test showed 0 image pixels, then 466,740). `bindHF` repaints the current frame when the images land; a hand-driven page awaits `stack.ready()` first. Which image a thumbnail shows is a property of the point, never of its screen position (an earlier version picked by `Math.round(x)` and the pictures flickered as the cloud turned).
- **Type sizes come from the SHORTER frame side, and each part fits the safe rect.** `c.s = H / 1080` is 1.78 on a 1080 x 1920 frame, which put `flankWords` words at x -254 and `behindSubject` labels 1,800 px wide on a 1,080 px frame. The round 4/5 type parts scale from `min(W, H) / 1080` and shrink to fit (`flankFitK`, `iconMergeFit`, the label fit, `electricGeo`); they never grow. A phrase that has to shrink below about 55% should be split across shots (`lintFlank`).
- **A panel that bobs on a fixed period breaks a loop.** `hexMosaic` with `loop: L` and a `panel` repeated exactly only when L was a multiple of 4 s (the bob period); the bob now makes a whole number of swings per loop. When a loop claims an exact seam, every periodic term of the part must be a whole number of cycles per loop.
- **Layers that import across modules need both modules staged.** `layers/canvas2d-r45.js` reads `../type/gfx/pathsample.js` and `media.js`; `templates/_shared/compose.mjs` stages `layers/` and `type/gfx/` side by side under `assets/mp/`, so a template that mounts these layers works unchanged. A copy of `layers/` on its own would not.
- **A gfx part's `dur` is its hold, not its length.** `life()` adds `inF` before it and `outF` after it, so a `lowerThird.docSuper` placed with `dur` equal to the shot length fades out over the NEXT shot (the 4 + 6 frame edges). Subtract the edges (`templates/multi-voice-doc` `supers.edgeF`) when a super must end on a cut.
- **Real UI is small on a 16:9 frame.** At `scale: 1` the kit uses true UI sizes (30-34 px body); for video use `scale` 1.3-1.6 and check a 360 px wide still.
- **A missing `source` is refused, not drawn.** `chart.scatterFrontier` (per point), `ui.dataTable` and `ui.costTicker` render a red "needs a source" card in place of the numbers, and their cue list collapses to one `sfx/ui/error`. A blank or whitespace-only string counts as missing. If a film shows that card, add the `source` string; do not hide the card. `type.paramReadout` does not refuse: a blank `source` falls back to its default "illustrative values" label.
- **Dense parts size their type from the shorter frame side.** `ctx.s` is `H / 1080`, which blows type up 1.78x on a 1080 x 1920 frame; `chart.scatterFrontier` and `ui.dataTable` use `W / 1080` on tall frames so a 9:16 table keeps its 16:9 type size. `ui.dataTable` also picks its own box and scale for the frame shape when you pass none: 9:16 gets a phone layout (numerals 12.3 px on a 360 px wide phone), 16:9 the desktop / TV box at scale 1, where a 6-row table is 6 px on a 360 px wide frame. Passing `box` or `scale` turns the auto choice off. A 16:9 table that must read on a phone: at most 4 rows, `scale: 2`, `box: [0.02, 0.02, 0.96, 0.96]` (12.0 px, tested). `ui.branchTrace` is a landscape diagram and overflows a 9:16 frame: put it on a 16:9 plate.
- **Anchors: two time bases.** `caption.sceneBubble` and `ui.costTicker` take `[x, y]` frame fractions, a track `[[t, x, y], ...]` where `t` is seconds since the part's `at` (local time), or `layout.cornerPin` data (`{corners}` / `{keys: [{t, q}]}`, `units`, `uv`) where `t` is COMPOSITION time, so the pinned layer and the chip share one track. `caption.sceneBubble` word times (`s`, `e` of words.json) are local too: a `words.json` from a take that starts at 2 s must be offset by the part's `at`, or the words arrive 2 s early. Scale about the right point: the docked bubble scales about its top-left corner, the free bubble about its tail side, so the docked box sits exactly in the list card.
- **`ui.branchTrace` runs are linted.** `run` must name fork ids that exist, one pick per step; otherwise the part draws a red "does not match the diagram" card instead of a wrong diagram. An empty `run` means every step takes its correct fork (a pass).

- **`scramble` swaps glyph text.** Use the canvas renderer or `driveType`, not `bakeType`.
- **`flipSplit` on canvas is a vertical squash.** The DOM version uses a real rotateX.
- **Safe zones conflict across sources.** `conservative` is the union, flagged `verify: true`.
- **Mask-rise type is clipped while it rises.** A frame grabbed mid-reveal shows clipped lines, which is correct. Judge legibility after the reveal settles: check the hold frame, not the first 14 frames.
- **Emphasis scale can collide.** At 1.15x, an emphasised word can overlap its neighbour ("So I flipped" in the talking-head demo). Add tracking or lower the emphasis scale for long words.
- **Some ffmpeg builds have no libass** (the one the pack was built with does not). Burn captions through the type module or PNG overlays, not the `subtitles` filter.

- **Canvas card systems load pictures once.** `mountCards` / `mountBoard` start URL images at mount; mount at module run so the page load waits for them, or pass decoded images or canvases. A picture that is not decoded yet draws the card back (a dark slot on the board), never a crash.
- **A cached plan hides a random number from every in-process check.** A plan built once per process (hexMosaic's `hexPlans` Map) answers every seek the same, so forward and shuffled order agree even with a `Math.random` inside it; a second render worker builds a different plan. Shuffled-seek checks only prove purity within one process: `node tools/tests/xproc-hash.test.mjs` hashes every node-renderable part in two fresh processes with different call histories (CI).
- **SVG def ids are page-wide.** Every `<svg>` in a page shares one id namespace and `url(#id)` resolves to the FIRST element with that id, so two `chart.line` items in one host (defs named `lc` / `lg` by hand) clipped the second chart with the first one's progress. `renderInner` now suffixes every id an item defines (and its `url(#...)` references) with a hash of that item's markup; write ids with `uid()` in new parts anyway, never reference a gfx def from outside by its literal name, and keep `href="#id"` (`<use>`) out of parts or extend `nsIds` first (`type/tests/ids.test.mjs` draws two items of every id in one host).
- **A zero step or radius is an endless loop.** `for (x = 0; x < W; x += step)` with step 0, or `rows = H / (1.5 * r)` with r 0, never ends (hexMosaic radius 0 ran out of memory; connectorLabel `gridStep: 0` built a 3 GB string). Every loop-driving number is clamped by `type/gfx/limits.js` (gfx ids) and `layers/limits.js` (Canvas2D kinds, backgrounds) through `type/gfx/safe.js saneParams`: NaN or Infinity reads as the default, a count above its maximum draws the maximum. Add the parameter to the table when you add a loop; `node tools/tests/fuzz-params.test.mjs` renders every part with 0, -1, NaN, Infinity, 1e9 and 1e-6 and fails on a hang.
- **Corner pin sits on top of the plate.** A 3D object passing in front of the pinned plane is not occluded by it: keep foreground props out of the pinned quad (the cards demo moves its panel outside the icon orbit for this reason).

## Layers and camera

- **Overlay grain behaves like midBias 1.** It is quiet in shadows and highlights. For exact kit grain use the Finisher.
- **A URL `logo` on `brandField` (and `images` on `embeddingCloud` / `hexMosaic`) loads once, shared by every frame.** `await stack.ready()` before the first frame; until a source is decoded, or if it failed, the placeholder is drawn. A second private loader in `canvas2d.js` used to start the load inside `draw()`, so frame 0 showed the placeholder and later frames the logo (fixed 2026-10-15; `layers/tests/r45.test.mjs` checks frame 0 after `ready()` with an async fake `Image`).
- **Plate-based effects need plate pixels.** Bloom, halation, chroma, lens and diffusion only run in the Finisher, so a DOM-only composition cannot do them.
- **No double finishing.** The `launch-studio` plate already bakes bloom, vignette and grain. `lintStack` and `lintOverlayStack` warn when you stack them twice.
- **meshGradient bands without grain.** Big slow radial gradients in 8-bit band; keep `grain` at 0.02 or more (the default is 0.04). The hologram beam is a screen blend, so it disappears on white plates.
- **Grades are starting values** judged on synthetic stills. Re-judge them on real footage.
- **Whip blur needs subframe sampling** in the render loop (8 or 16 subframes). A 2D whip alone exposes black.

## 3D objects and kit

- **Seek-safe objects.** No `Date` or `Math.random` anywhere; everything renders from `t`.
- **Determinism QA.** Run the frame renderer's `--qa` mode (determinism, seam and console checks). A failing seam check is expected for non-loops.
- **Prop polish varies by distance.** The laptop aluminium reads slightly flat and the mug is perfectly symmetric. Both are fine at template distances but not photoreal at macro distance; use a Blender render (not part of this repo) for a photoreal hero.
- **No third-party logos on props.** If you pass a real logo texture, the type layer must carry the trademark line.
- **logo-extrude slices are hollow.** The sliced beat uses two clipping planes, so the cut face shows the inside of the extrusion (no cap). Fine at speed, not for a long hold. Clipping planes live in world space; `set()` recomputes them from the part's matrix every frame.
- **Run the 3D templates before `beat-edit` and `talking-head`,** which use their renders as footage.

## Blender

- **EEVEE drops the emission of a fully transparent surface.** In the default dithered mode, `Add(Emission, Transparent)` renders nothing: the pixel is discarded before its emission counts. For glows on see-through surfaces, mix Transparent and Emission by a coverage factor (`blender/lib/kit.py` x-ray pass), or set the material to `BLENDED` (`materials.pure_emission`).
- **Keyed values inside a shader node group animate fine** (`kit.pass_group` keys one `stage` value for every pass material), but check a frame from each state: a wrong blend shows up as the previous pass, not as an error.

- **Cycles writes timing into the PNG.** `cycles.ViewLayer.*_time` tEXt chunks (total, render, synchronization time) land in every frame whatever the stamp settings, so two renders with equal pixels hashed differently. `run.py` now strips them after each render (`lib/util.py` `strip_png_timing`; the pixel data is untouched). With that, Cycles on the CPU (`--device cpu`) gives the same file hash in two separate processes (cableTangle, frame 48, 480p, 16 samples; `blender/tests/cable_tangle.sh`). The GPU stays visually, not bit, identical (`DETERMINISM.md`).
- **Measure a bulb-out plate in the PNGs, not the keys.** The recipe keys the light and filament per whole frame, but the denoised pixels fade over a few frames after the key (an afterglow at 0.32, then a decay), so the test looks for the first frame from which the bulb stays dimmer, not for a single-frame jump. The 2-frame flicker before a bulb dies recovers on purpose and must not count.

## Environment and process

- **A demo MP4 that is on your disk leaks into the committed catalog.** `catalog/build.py` links a template's `out/<name>.mp4` when the file exists, but the MP4s are gitignored, so a catalog built next to them fails `tools/pages_site.py` on a clean clone (`MISSING templates/proof-film/out/proof-film.mp4`). Move the MP4s away, run `catalog/build.py` and `tools/count.py --write`, then put them back.
- **Leave disk headroom for renders.** `templates/_shared/render3d.sh` prints free space first and asks the renderer to stop under 10 GiB free. On macOS a render killed with exit code 143 often means the disk filled up.
- **A hidden browser pane throttles animations.** `document.hidden` freezes counters and reveals, so check `visibilityState` before debugging. A hidden Chrome also stalls X and LinkedIn video uploads.
- **A demo page opened in a plain Chrome tab has a zero-height `#root`.** `#root { height: 100% }` collapses without HyperFrames sizing it, so a screenshot is blank paper. Add `html, body, #root { width: 1920px; height: 1080px }` before screenshotting, then dispatch `hf-seek` events to step time (the same frame comes out in any seek order: `templates/demo-r45-ui` was checked forward and reversed in two browser sessions).
- **Image models garble UI.** Never let one redraw UI or text. Generate the room and composite the real screenshot.
- **References are craft, not copy.** Learn the method from reference work and never build a literal replica.
- **Write it down the same day.** Every new gotcha goes into this file and the module README.
