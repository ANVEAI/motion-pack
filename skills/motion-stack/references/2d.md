# 2D: animation engines for seeked video (GSAP, Anime.js, Motion, Motion Canvas, Remotion, plain functions)

On 13 Oct 2026 we built the same 4 s shot in six ways and checked each at 100% on the same frames. The shot was 1080x1920:
- a masked word reveal and a per-character reveal;
- a highlight wipe;
- a ₹0 → ₹38,400 counter;
- a circle → rounded-square → box morph;
- an icon on a curved path;
- a spring pop and a hold.

| engine | gates (G1–G3 / HyperFrames) | quality | cost to integrate | verdict |
|---|---|---|---|---|
| **GSAP 3.15** (SplitText, MorphSVG, MotionPath, CustomEase; all free) | pass / pass, bit-exact after 2 settings | 4/5 | 33 lines, native HyperFrames adapter | **ADOPT: default 2D engine** |
| **Plain pure functions of t** (no library; the pack's ease and type code) | pass / pass, bit-exact on the first run | 5/5 | 53 lines on top of shared helpers | **KEEP: component layer and reference** |
| Anime.js 4.5 | pass / pass, after 4 rules | 4/5 | compact; needs explicit registry | ADOPT-FOR small flourishes |
| Motion 13.4 (vanilla) | pass / pass, after bypassing most of its API | 5/5 | about 40 lines reimplementing a pure-function layer | REJECT for video |
| Motion Canvas 3.17 | pass (player element) / own exporter | 5/5 | 220 scene lines, Vite pinned to 5, 106 MB, last code commit Feb 2025 | KEEP-CURRENT (nothing gained) |
| Remotion 4.0 | pass, bit-exact | 3/5 (path morph faceted for about 0.33 s) | 224 MB + a 94 MB browser download + webpack; output enters HyperFrames only as a lossy clip; paid licence above 3 employees | KEEP-CURRENT (nothing gained) |

**Job → engine:**
- **HyperFrames 2D composition** (reveals, counters, shapes, icons, springs): GSAP.
- **Shared components and reference stills:** pure functions through `hf-seek`.
- **Morph between different path structures:** GSAP MorphSVG, or author both shapes with the same command structure. Matched structures morph exactly with any engine.
- **A small MIT-only flourish:** Anime.js through `window.__hfAnime`.
- **A CSS-only spring:** generate a CSS `linear()` easing at dev time with the free `motion` package (`createGeneratorEasing` + `generateLinearEasing`). Its maximum error vs the closed form was 2.7e-3 of full scale.
- **Maths and diagram explainers:** a dedicated diagram engine. Motion Canvas added nothing there.

## GSAP, the seek-safe way

```html
<div id="root" data-composition-id="main" data-start="0" data-duration="4" data-width="1080" data-height="1920"> ... </div>
<script src="vendor/gsap.min.js"></script><script src="vendor/CustomEase.min.js"></script>
<script src="vendor/SplitText.min.js"></script><script src="vendor/MorphSVGPlugin.min.js"></script>
<script>
  gsap.registerPlugin(SplitText, MorphSVGPlugin, CustomEase);
  CustomEase.create('enter', '0.16,1,0.3,1');            // a cubic-bezier house curve, reproduced to 0.15 px
  gsap.config({ force3D: false });                       // no translate3d promotion → bit-exact rasters
  Promise.all([document.fonts.load('800 136px Manrope'), document.fonts.ready]).then(() => {
    const tl = gsap.timeline({ paused: true });
    const s = SplitText.create('#l1', { type: 'lines,words', mask: 'lines' });
    tl.from(s.words, { yPercent: 120, duration: 0.5, stagger: 0.07, ease: 'enter' }, 0);
    tl.fromTo('#counter span', { innerText: 0 }, { innerText: 38400, duration: 2.6, ease: 'power2.out',   // power2 = cubic
      modifiers: { innerText: (v) => '₹' + Math.round(v).toLocaleString('en-IN') } }, 1.0);
    tl.seek(tl.duration()).seek(0);                      // warm pass: MorphSVG re-serialises its start path on first render
    window.__timelines['main'] = tl;                     // register only after the build; key = data-composition-id
  });
</script>
```

**Render-safe GSAP rules** (worth more than most of the general GSAP advice):
1. **`power2` is cubic and `power3` is quartic.** A counter with `power3.out` ran 0.27 s ahead of a cubic spec. A popular Remotion→HyperFrames guide gets this wrong too.
2. **`tl.seek(t)` suppresses callbacks.** Anything you drive from `onUpdate` does not update. Tween properties instead (`innerText` + `modifiers`), or call `seek(t, false)`.
3. **Timelines are thenables.** `window.__seek = (t) => tl.seek(t)` returns the timeline, a test harness awaits it, and the run hangs. Wrap it in braces.
4. **Set `gsap.config({ force3D: false })`.** The default promotes elements to 3D layers, which gave 1-LSB raster differences between passes.
5. **Do one warm pass** (`tl.seek(tl.duration()).seek(0)`) before registering.
6. **Put `immediateRender: false` on the later of two `fromTo` tweens** of one element.
7. **No negative `z-index`.** Use `isolation: isolate` plus positive z-index.
8. **MotionPath is arc-length parameterised.** A spec written in Bezier-t needs a closed-form path function (up to 11.6 px apart otherwise).
9. **Natural-structure morphs lean mid-way** (about 5% of the shape area off a symmetric lerp). `smooth: 'auto'` halves that, and matched structures remove it. Leave `shapeIndex` on auto: forcing it made the morph worse.

## Pure functions through `hf-seek` (the pack's own layer)

```html
<div id="root" data-composition-id="main" data-no-timeline data-start="0" data-duration="4" data-width="1080" data-height="1920"> ... </div>
<script type="module">
  function draw(t) { /* set every property of every element from t; remember nothing */ }
  const ready = init();                                                     // fonts + DOM split
  window.__hf = window.__hf || {}; window.__hf.buildReady = { main: ready }; // hold the first frame until ready (must not wait on rAF)
  window.addEventListener('hf-seek', (e) => draw(e.detail.time));
</script>
```

- A root with no GSAP timeline needs `data-no-timeline`. Otherwise lint errors and the producer polls for 45 s per render.
- For async work inside the event, call `e.detail.waitUntil(promise)` synchronously inside the listener.

## Anime.js v4, the four rules

```js
const tl = anime.createTimeline({ autoplay: false });
tl.set(words, { y: '120%' }, 0)                                   // 1. explicit initial states: v4 children don't apply from-values early
  .add(words, { y: ['120%', '0%'], duration: 500, delay: anime.stagger(70), ease: anime.cubicBezier(0.16, 1, 0.3, 1) }, 0);
tl.seek(4000); tl.seek(0);                                         // 2. warm pass (svg.morphTo rewrites d at build time)
(window.__hfAnime = window.__hfAnime || []).push(tl);              // explicit registry: there is no auto-discovery in v4
// 3. for your own harness: rewind before a backward seek; bare backward seeks left stale values (17–30 dB failures)
// 4. splitText({ accessible: false }), or it injects a hidden duplicate of the line (and of any id inside it)
```

- v4 has no callable `anime()`. It uses `ease:`, not `easing:`.
- `createSpring` is deprecated; use `spring()`.
- `timeline.seek` also returns a thenable.

## Why not Motion, Motion Canvas or Remotion for this pipeline

- **Motion** (free) is built for realtime UI:
  - `animate(path, { d })` silently does nothing.
  - `opacity` always becomes a native WAAPI animation, and those flaked in screenshots.
  - Writes land on its next frame, not inside the `time` setter.
  - `splitText` and `AnimateNumber` are paid Motion+.
  - Its spring generator is the useful part.
- **Motion Canvas** renders well (54.5 dB vs the DOM baseline), but it is a separate world:
  - its own editor and exporter (a `?render` URL flag runs the real exporter without clicks);
  - Vite 5;
  - no text splitter;
  - a 4.0 s scene came out at 122 frames because of float accumulation.
- **Remotion** is fast and deterministic (3.8 s CLI render for the shot), but:
  - its path morph (a d3 port) facets natural shapes;
  - it needs a bundler and its own Chrome download;
  - it has no HyperFrames adapter;
  - companies with more than 3 employees need a paid licence;
  - **its skill pack had wrong advice:** a cubic→`power3` easing map, a top-level-await font loader that doesn't bundle, an API that doesn't exist, and scripts missing from the folder.

## Paint order is part of the spec

One engine wrote `transform: none` where the others leave an identity matrix. That changed which element painted on top: a period ended up under a highlight bar. Never let stacking depend on what an engine leaves behind; state it in CSS (`position: relative; z-index: 1`).
