# motion-pack / templates

There is one starter per genre. Each one has a `config.mjs`, which holds the editable `CONFIG` block plus a pure `buildPlan(C)`, and each has a rendered demo.

A plan is a single JSON file, `out/plan.json`, containing shots, transitions with their reasons, the SFX cue sheet and the lint results. The same plan drives the picture, the sound and the checks.

A plan may also say what the sound is meant to do, so `ears` and the critic judge a planned shape as intended: `"audio": {"mode": "music" | "vo" | "continuous", "quiet": [{"t": [a, b], "kind": "open" | "dip" | "gap" | "hold", "why": "..."}], "events": [seconds], "role": "proof" | "explainer" | "hype" | "trailer" | "vo_doc" | "brand_launch"}`. All fields are optional (no `audio` means mode `music` and no planned quiet); the templates do not write it yet, so add it in a template's `make.mjs` plan or by hand. See `ears/README.md` ("What the plan can tell ears") and `skills/motion-pack/references/critic.md`.

Run the three.js templates before `beat-edit` and `talking-head`, because those two use the 3D renders as their footage.

**The three.js templates (`film-scene`, `character-spot`, `style-scene`) render through `templates/_shared/render3d.sh`,** always from the repo root: its arguments are the template folder, the page and the aspect (`<dir> <page.html> <wide|tall> [crf]`), so `../_shared/render3d.sh film-scene ...` cannot work from any folder. Before the first run:
- `npm i --no-save puppeteer-core` in the repo root (the render driver `tools/render.mjs` finds it there; it is not a dependency of the pack; a plain HyperFrames template does not need it, but `demo-cards-objects` and `demo-r3-fx` render a 3D plate on their first run and do);
- Chrome or Chromium with a hardware GPU (the driver refuses software WebGL; `--allow-software` is for debugging only), and network access, because the pages load three.js 0.160.0 from jsDelivr through an import map;
- ffmpeg, the Python packages from `requirements.txt`, a built sound library and 10 GiB of free disk (the script stops under that);
- the browser test suites (`bash layers/tests/run-all.sh` and the module tests) also want `gsap` and `three`: `npm i --no-save puppeteer-core gsap@3.14.2 three@0.160.0` (CONTRIBUTING.md). Renders do not.

## How a template wires the other modules (by id only, never copied)

| convention | resolved by | what happens if the module has not shipped it |
|---|---|---|
| `transitions/<name>` (key, kebab form, alias, or grammar id: `cut`, `smash`, `dip-to-black`, `crossfade`, ...) | **wired**: `_shared/txplan.mjs` turns each windowed cut into an overlap window (`txWindow` from `transitions/lib/tx-core.js`, swap on the exact cut frame, clamped to half of each neighbouring shot) and stretches the outgoing/incoming clips with `span()`; `_shared/adapters/transitions.mjs` registers every DOM-capable id and drives `transitions/lib/tx-dom.js applyDom` from one GSAP proxy per window. `out/tx.json` lists the windows. | `cut`/`smash` = deliberate hard cut. Every other visual transition plays in a DOM template: 26 have an exact DOM back-end and the 23 GL-only looks (glitch, ink, filmBurn, lightLeak, morph, zoomThrough, pagePeel, pixelSort, maskReveal, ...) a DOM approximation (`kind: 'dom', approx: true`: the timing, the swap frame and the sound are exact, the look is not; `transitions/README.md` says which). Only `speedRamp` (timing-only, use `cuts/retime.py`) is logged as `transitions todo` and hard-cuts; for the exact GL look use `transitions/lib/tx-gl.js` with canvas sources. Unknown id -> hard cut + `tools/check_ids.py` fails. |

## Lint (in `cues.mjs`, results written into `plan.json`)

`lint.proof` and `lint.tx` are gates, not printouts. `cues.mjs` prints the problem, still writes `out/plan.json` (its `lint` object lists it) and exits 2; every genre template's `make.mjs` runs it first (`runPlan`), so a failing lint stops the build before anything is staged, mixed or written (`render3d.sh` stops too, it runs with `set -e`). The part demos have no `config.mjs` and build their own plan, so they run the same gate on it (`lintPlan` + `lintStop` in `compose.mjs`, exit 2 before `stage()`; demo-r3-fx and demo-cards-objects render their plates before the plan). A shot's transition may be spelled `tx` or `transition`; either needs a `txReason` unless it is a hard cut. One documented waiver: `--allow-lint` (`MP_ALLOW_LINT=1` for `render3d.sh`) lets the build go on and records the waived problems in `plan.lint.allowed`; never waive a stat that has no source. `tools/tests/test_lint_gate.py` runs it on every shipped template, on a bad claim and a bad transition, and on three part demos, and checks that every tracked `make.mjs` gates before it stages.

- **`lint.proof` (gate):** every claim in the plan's `claims` that contains a digit needs a `source` that names where the number comes from. A blank source, filler ("n/a", "x", "tbd", "trust me") and a generic one ("internal benchmark", "in-house data", "our data", "self-reported", "me") are refused in any spelling (case, hyphens, underscores and a "source:" prefix are normalised first); the check is on form, not truth. There are no fabricated stats. `claims` is what a template puts there (the ad's and the worked example's proof lines, the proof film's number fields); copy outside it, such as a hook or a headline, is not scanned, so keep every stat in a claim. The ad demo uses copy with no numbers.
- **Honesty gate (`proof-film/honesty.mjs`):** stricter, because a proof film is made of numbers. Every number field needs a `source` AND a `method` that say something (blank, filler such as "n/a" and a method that repeats the source count as missing), a number may only appear through a number field (never in prose, the brand name, the URL, an axis unit or the VO transcript: a digit in any script, a currency or percent sign, a number word, even split by a zero-width character), the VO transcript has to be a readable `[{w, s, e}]`, the claim is at most 6 words with one accent word, `trace` is refused on 9:16, and `node make.mjs` exits 2 naming the field before it builds anything. It feeds `lint.proof` too.
- **`lint.tx` (gate):** any transition other than a hard cut needs a `txReason`, written as a Murch reason.
- **`lint.pace` (reported, not enforced):** checks ASL and the longest shot. Shots marked `hold: true`, such as the hero reveal and the end card, are exempt from the longest-shot check.
- **Ad brand cue:** the ad also reports `brandCueAt` against the platform's `brandCueBy`.

## Demo honesty

- **Placeholder content:** "Orbit" is a fictional placeholder brand, and every line of copy is placeholder.
- **Talking-head input:** the demo input is our own film-scene render, and its transcript (`words.json`) is hand-timed placeholder text. It proves the mechanics (autocut, captions, B-roll, punch-in, lower third). It is not a real voice edit.
- **Multi-voice documentary:** the demo ships with no footage. `clips.json` holds generated placeholder words at about 160 wpm and `src: null`, so every speaker renders as a labelled "your interview clip here" card over a guide signal (shaped noise at the word timings, plainly not a voice). Names, roles and the customer line are placeholders and the proof card carries a `placeholder` source label. Supply your own interview MP4s and whisper word timings (`src`, `words`) and the same plan cuts them; the cold open is `cuts/cutgen.py voices-open`, so the template and the CLI never disagree. Name supers are `lowerThird.docSuper`; `CONFIG.supers.part` is the one line to change when `lowerThird.personalTag` lands.
- **Mime-style spots:** we borrow the edit grammar only (docs/evidence/edit.md section 10). The character is our original worker.
- **Human templates (tutorial, vlog-personal, podcast-clip, founder-story, course-lesson):** the demos ship with no footage and no people: labelled silhouettes, a fictional desktop drawn in SVG ("PLACEHOLDER RECORDING · fictional app"), labelled photo and B-roll cards, and a guide signal (shaped noise at the hand-timed words of each `transcript.example.*`, plainly not a voice). Set `src` and `voice.words` and the same plan edits your footage; `docs/bring-your-footage.md` covers formats, VFR, sync, fillers and breaths.
- **Proof film:** "Acme Reader" is a fictional placeholder brand and every number in the demo is a labelled placeholder: its source is "illustrative placeholder, replace", each one has a method line, and the frame prints ILLUSTRATIVE next to them (the scatter and table parts add their own footnotes). Nothing is borrowed from a reference or a real product; replace the numbers with measured ones (real source, real method), set `illustrative: false`, and the labels go. The optional VO demo (`words.example.json`) is hand-timed placeholder text and a labelled guide signal, never a voice.

## One project file for every template

`templates/_shared/project.schema.json` is ONE file a person or an agent edits. Each genre template's `config.mjs` exports `PROJECT_MAP`, which maps the project's `brand.*`, `text.*`, `media.*`, `voice.*`, `music`, `claims`, `length`, `aspect` and `platform` onto its CONFIG. It also exports `ASPECTS`: native, relayout or manual, for each of 16:9, 9:16, 1:1 and 4:5.

`node make.mjs --project p.json [--aspect 9:16] [--set k=v]` applies the project, then the per-template `overrides`, then `--set`. An empty project builds the byte-identical plan (`node tools/tests/project.test.mjs`).

The `mp` CLI (`tools/mp`) wraps it all: `mp new ad ~/Movies/x`, `mp set ...`, `mp render`, `mp check`. See `docs/EDIT-WITHOUT-CODE.md`.

The ad template's 9:16, 1:1 and 4:5 come from the generic card re-layout (`_shared/relayout.mjs`): type is re-fitted into the safe rect, not cropped.
