**motion-pack is a video-production kit that AI agents (and people) can drive by id.** It has transitions, cut grammars, sound effects and music synthesised in code, finishing layers, kinetic type and captions, camera moves, three.js props and a rigged character. Five genre templates wire them together: an ad, a short-film scene, a wordless character spot, a talking-head edit and a beat edit. Every component is a pure function of time, so any frame can be rendered alone, renders repeat exactly, and the audio regenerates bit for bit. Everything renders in [HyperFrames](https://github.com/heygen-com/hyperframes) compositions, in a three.js studio kit, or in both. A skill tells an agent which part to pick for which shot. Nothing in the pack is sampled, scraped or generated by a paid model.

## Requirements

| need | for | tested with |
|---|---|---|
| Node.js 20 or newer | templates, transitions, type, camera, tests | 22.23 |
| Python 3.11 + `pip install -r requirements.txt` (numpy, scipy, numba, soundfile, Pillow, matplotlib, pytest) | sound synthesis, mixing, cuts, catalog, previews | 3.11.7 |
| ffmpeg with libmp3lame | mixes, muxing, contact sheets, audio previews | 8.0.1 |
| Google Chrome or Chromium | HyperFrames renders, three.js renders, browser tests | current stable |
| HyperFrames 0.8.142 (through `npx`, no install) | rendering the DOM templates | 0.8.142 |
| A hardware GPU | WebGL: three.js templates, GL transitions, browser tests (software GL is refused) | Apple M-series (ANGLE Metal) |

Optional, for the browser tests and the GPU render driver: `npm i --no-save puppeteer-core gsap@3.14.2 three@0.160.0` in the repo root (or set `PUPPETEER_CORE_DIR`, `GSAP_JS`, `THREE_DIR`; see `tools/chrome.mjs`). Templates load GSAP 3.14.2 and three.js 0.160.0 from jsDelivr at render time; neither is vendored.

## Quickstart (5 minutes)

```bash
git clone https://github.com/ANVEAI/motion-pack && cd motion-pack
pip install -r requirements.txt

# 1. Build the sound library (or download the WAV masters from the latest Release, see below)
python3 sfx/build_library.py         # every synthesised sound -> sfx/library/ (under a minute)
python3 music/build_music.py         # beds, stingers, sonic logos -> music/library/ (1-2 minutes)

# 2. Make the 15-second ad: plan, SFX + music mix, HyperFrames page
cd templates/ad
node make.mjs --set length=15

# 3. Render it
npx --yes hyperframes@0.8.142 render . -o out/ad-15.mp4 --crf 23
```

To make your own video, copy the closest template folder, edit only the `CONFIG` block in its `config.mjs`, and keep every reference as an id. `python3 tools/check_ids.py` should report 0 unresolved before and after your edit. The three.js templates (`film-scene`, `character-spot`) render on the GPU with `bash templates/_shared/render3d.sh templates/character-spot scene.html wide 23`.

## Use with Claude Code

The repository is both a Claude Code plugin and a plugin marketplace (marketplace `anve`, plugin `motion-pack`):

```text
/plugin marketplace add ANVEAI/motion-pack
/plugin install motion-pack@anve
```

The skill then loads as `/motion-pack:motion-pack`, and Claude reaches for it when you ask for a video. The skill works on a clone of this repository, so run Claude Code from your clone (the plugin copy carries the skill text; renders and audio builds happen in the clone).

Manual install, without the plugin system: copy or symlink the skill folder into your skills directory.

```bash
ln -s "$PWD/skills/motion-pack" ~/.claude/skills/motion-pack      # all projects
# or: mkdir -p .claude/skills && ln -s "$PWD/skills/motion-pack" .claude/skills/motion-pack   (this project only)
```

## Use with other agents

`skills/motion-pack/SKILL.md` is written in the open [Agent Skills](https://agentskills.io) format: a folder with a `SKILL.md` (name, description, instructions) plus reference files. Agents that read that format (the [client list](https://agentskills.io/clients) includes Codex, Gemini CLI, Cursor, GitHub Copilot, OpenCode and Goose) can load the folder as it is. Any other agent can use the pack through plain files: this README, the module READMEs, the JSON manifests and the command-line scripts. There is no server and no API key.

## The determinism contract

Every component is a pure function of `t` (or of a frame number and fps). There is no `Date.now()`, no `Math.random()`, no wall clock and no simulation state carried between frames; randomness comes from seeded generators.

- **Picture:** `renderAt(t)`, `applyDom(p)` and the HyperFrames bindings draw any frame on demand, so you can seek anywhere, render frames out of order and get the same pixels on a re-render. `transitions/renders/hashes.json` records a cross-launch check of every transition's key frames.
- **Sound:** every sound and music cue is a recipe `fn(seed)`. Re-running the builders reproduces the library bit for bit: all 288 sounds, every music bed and stinger, and every LUT matched SHA-256 when this release was prepared. The manifests store a hash of each buffer.
- **Timing:** a sound cue for visual frame F puts its anchor sample on `(F + 1) x 48000 / fps`, and a transition's swap lands exactly on the cut frame, because transition windows are integer frames.

Determinism is what lets an agent plan a whole edit in JSON, render it in pieces, and trust the result.

## The catalog

<https://anveai.github.io/motion-pack/catalog/> lists every component with a thumbnail or demo, its parameters and its pairings (which sound goes with which transition, which bed with which bundle). It also works offline: open `catalog/index.html` straight from disk, or run `python3 -m http.server` in the repo root and visit `/catalog/`. Rebuild it with `python3 catalog/build.py`; it makes zero external requests.

## Heavy media: regenerate or download

The git tree carries code, manifests and small previews only. The full-size media is either rebuilt by the pack's own scripts or attached to each GitHub Release.

| media | in git | regenerate | Release asset |
|---|---|---|---|
| Sound effects, WAV 48 kHz 24-bit | MP3 previews (`sfx/previews/`) | `python3 sfx/build_library.py` (bit-exact) | `motion-pack-sfx-wav-<version>.zip` |
| Music beds, stingers, sonic logos, WAV + beat-grid sidecars | MP3 previews (`music/previews/`) | `python3 music/build_music.py` (bit-exact) | `motion-pack-music-wav-<version>.zip` |
| Full-size PNG renders and contact sheets | JPEG previews | the module's sheet script, then `python3 tools/make_previews.py --images` | `motion-pack-renders-fullres-<version>.zip` |
| Demo mixes and stems | none | `python3 music/demo/demo_mix.py`, `python3 sfx/demo/demo_sfx_reel.py` | `motion-pack-demo-audio-<version>.zip` |

Each Release lists a `SHA256SUMS` file for its zips. Unzip the WAV masters at the repo root (they land in `sfx/library/` and `music/library/`). The MP3 previews are for listening only: MP3 adds encoder delay, so anchors, beat grids and mixing always use the WAV masters.

## Optional third-party sets

Nothing third-party is vendored. `scripts/fetch-external.sh` downloads pinned, permissively licensed sets (Lucide and Phosphor icons, Fluent Emoji, Kenney and OwlishMedia CC0 audio) from their original sources into `external/` (gitignored) and checks every file against `scripts/external.lock`. Audio from those sets enters the sound catalogue only through `sfx/tools/check_origin.py` and `sfx/tools/catalog_import.py`. See [THIRD_PARTY.md](THIRD_PARTY.md).

## Checks

| check | command |
|---|---|
| Cross-module ids resolve | `python3 tools/check_ids.py` |
| Python (cuts, sfx, music) | `python3 -m pytest -q cuts/test_cutgen.py cuts/test_retime.py sfx/tests music/tests` |
| Transitions core + lint | `node transitions/tests/core.test.mjs && node transitions/tools/lint.mjs` |
| Camera maths | `node camera/tests/camera.test.mjs` |
| Browser tests on a real GPU (layers, type, camera, DOM transitions) | `bash layers/tests/run-all.sh` |
| Sound QA, measurement only | `python3 sfx/qa.py`, `python3 music/qa.py` |

CI runs the checks that need no GPU on every push (`.github/workflows/ci.yml`).
